# 프로젝트 문서 안내

문서의 목적에 맞춰 내용을 구분한다. 기획서에 작업 진행 상황이나 조사 메모를 덧붙이지 않는다.

| 문서 | 남길 내용 | 작성·갱신 시점 |
|---|---|---|
| [기획서](development-plan.md) | 요구사항, 주요 확정 결정, MVP 범위, 합격 기준 | 요구사항이나 주요 결정이 바뀔 때 |
| [최초 보존 개발계획서](development-plan-initial.md) | 2026-10-06 v0.2·Git b632c30 원문. 최초 계획 대비 비교 기준이며 후속 요구사항으로 수정하지 않는다. | 고정 기준; 현행 기획서와 구분 |
| [검토·결정 기록](decisions/review-and-decisions.md) | 결제·요금 조사, 근거, 비교안, 잠정 의견, 미결정 사항, 날짜가 있는 최종 결정 | 조사·선택·결정할 때 |
| [작업 기록](operations/2026-10-07-document-cleanup.md) 및 operations/의 개별 기록 | 변경 목적·파일, 보존 범위, 백업·변경·검증 이력, 커밋·원격 반영, 미완료·다음 작업, 복원 방법 | 각 작업을 마칠 때 |
| [개발 보고서](development-report.md) | 실제 구현한 기능·변경 이유, 검증 결과와 한계, 남은 개발 범위 | 실제 구현이 시작된 뒤 구현 결과를 보고할 때 |
| [검수 사례](acceptance-cases.md) | 실제 기능 검수에 사용할 입력 사례와 기대 행동 | 사례를 선정·보완할 때 |

개발 보고서는 조사나 문서 정리 단계에서 미리 만들지 않는다. 구현 계획·잠정 의견을 구현 결과로 보고하지 않는다. 기존 작업 기록은 당시 이력과 증거로 보존하며, 필요한 구현 보고를 작성할 때 근거로 연결한다.

최초 계획과 실제 결과의 차이는 [개발 보고서의 비교 절](development-report.md#최초-개발계획-대비-결과)에서 확인한다. 현행 기획서는 변경된 요구사항, 최초 보존 계획서는 당시 계획, 개발 보고서는 실제 결과/차이를 각각 맡는다. 최초 Git 보존본은 v0.2이며 v0.1 본문 확인으로 확대하지 않는다.

주요 결정은 검토·결정 기록에 근거와 날짜를 남기고 확정 내용만 기획서에 반영한다. 작업 기록에는 요구사항을 다시 정의하지 않고 관련 기획·검토 문서를 연결한다. 검수 기준과 실제 검증 통과 여부는 구분한다.

## 현재 PC의 CRM 실행

외부 확장: [승인 설계](remote-access-design.md), [실행 계획](remote-access-plan.md), [구현·배포·검수 기록](operations/2026-10-13-remote-access.md). 실제 주소는 https://sp-sales-crm.piaoenya.workers.dev 이며 저장 업무·메모는 PC와 분리해 사용한다. 새 메일 수집에는 PC 연결과 Outlook 실행이 필요하다. 기능 구현과 남은 운영 검수는 작업 기록에서 구분한다. 현재 Windows가 4327을 예약한 상태의 PC 연결 검수에는 임시 14327 인스턴스를 사용하며 기본 실행 경로/주소 설정은 보존한다.

PC 수집 연결을 다시 실행할 때는 프로젝트의 [start-crm-sync.cmd](../start-crm-sync.cmd)를 사용한다. 실행된 로컬 Chrome 탭에서 기존 업무 계정으로 연결하고 Outlook을 실행한다. 새 메모는 연결 후 클라우드에 저장하며 기존 SQLite 파일은 보존한다. 외부 주소에서는 수집 PC와 연결되지 않아도 저장된 업무를 사용할 수 있다.

프로젝트 폴더의 [start-crm.cmd](../start-crm.cmd)를 더블클릭하면 로컬 서버를 확인·실행하고 Chrome에서 `http://127.0.0.1:4327/`을 연다. 이미 실행 중인 서버를 중복으로 띄우지 않는다. Windows 자동 시작이나 예약 작업을 추가하지 않는다. 기존 `.env`, 빌드, D 드라이브의 로컬 검토 자료를 사용하며 빠진 자료가 있으면 안내 후 중단한다.

실제 저장 업무와 메일 자동 확인에는 Chrome의 저장된 CRM 계정 연결이 필요하다. 한국 시간 평일10~18시 정각 확인은 해당 탭과 Outlook이 실행 중일 때 동작하며, 수동 확인 버튼은 언제든 사용할 수 있다. 새 버전 적용 후 기능 검수와 장기 실사용 합격은 개발 보고서·작업 기록에서 구분한다.
