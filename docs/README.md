# 프로젝트 문서 안내

문서의 목적에 맞춰 내용을 구분한다. 기획서에 작업 진행 상황이나 조사 메모를 덧붙이지 않는다.

| 문서 | 남길 내용 | 작성·갱신 시점 |
|---|---|---|
| [기획서](development-plan.md) | 요구사항, 주요 확정 결정, MVP 범위, 합격 기준 | 요구사항이나 주요 결정이 바뀔 때 |
| [검토·결정 기록](decisions/review-and-decisions.md) | 결제·요금 조사, 근거, 비교안, 잠정 의견, 미결정 사항, 날짜가 있는 최종 결정 | 조사·선택·결정할 때 |
| [작업 기록](operations/2026-10-07-document-cleanup.md) 및 operations/의 개별 기록 | 변경 목적·파일, 보존 범위, 백업·변경·검증 이력, 커밋·원격 반영, 미완료·다음 작업, 복원 방법 | 각 작업을 마칠 때 |
| 개발 보고서 | 실제 구현한 기능·변경 이유, 검증 결과와 한계, 남은 개발 범위 | 실제 구현이 시작된 뒤 구현 결과를 보고할 때 |
| [검수 사례](acceptance-cases.md) | 실제 기능 검수에 사용할 입력 사례와 기대 행동 | 사례를 선정·보완할 때 |

개발 보고서는 조사나 문서 정리 단계에서 미리 만들지 않는다. 구현 계획·잠정 의견을 구현 결과로 보고하지 않는다. 기존 작업 기록은 당시 이력과 증거로 보존하며, 필요한 구현 보고를 작성할 때 근거로 연결한다.

주요 결정은 검토·결정 기록에 근거와 날짜를 남기고 확정 내용만 기획서에 반영한다. 작업 기록에는 요구사항을 다시 정의하지 않고 관련 기획·검토 문서를 연결한다. 검수 기준과 실제 검증 통과 여부는 구분한다.
