# 실제 사례 확인 및 검수 사례 선정

- 목적: 개발계획서 0단계에서 실제 업무에 맞는 검수 사례 선정.
- 변경 파일: `docs/acceptance-cases.md` 신규 작성.
- 확인 근거: 사용자 요청에 따라 2026-10-06 Outlook 관련 고객 수신 1통, 고객 중간 회신 1통, HQ 문의 발송 1통 조회. 메일 및 첨부파일은 수정·발송·다운로드하지 않음.
- 보존: 기존 개발계획서 유지. 메일 원문과 개인 연락처는 문서에 복제하지 않음.
- 검증: 문서 재조회 및 검수 절차 9개 확인. 실제 CRM 기능 검수는 구현 전이며, 해당 업무의 HQ 답변·최종 고객 전달은 미확인.
- Git/원격: 상위 하네스 저장소 ignore 대상. CRM 전용 저장소 미설정으로 커밋·push 없음.
- 다음 작업: Outlook 수집 대상 범위 확인, 제품검색 및 반복 HQ 문의 사례 선정. 0단계 전체 완료로 판정하지 않음.
- 복원: 기존 파일 변경 없이 신규 기록만 추가.

## 초기 수집 기간 및 원본 자료 확인

- 사용자 결정: 초기 메일 최근 1개월, 이후 기간 확대 가능.
- 변경: 개발계획서에 기간 반영. 자료 위치는 ignored 로컬 `notes/source-locations.md`에 기록.
- 조회: 지정 루트 및 고객·Datasheet 폴더의 바로 아래 목록만 확인. 파일 본문·인증 자료는 읽지 않음. 원본 이동·외부 업로드 없음.
- 검증: 변경 후 문서 재조회, 개발계획서의 기간 반영과 notes의 Git ignore 상태 확인.
- 남은 결정: Outlook 대상 폴더, 실제 제품 원본 선정·최신성, AI·운영 조건.
- 복원: 개발계획서의 이번 기간 관련 문구를 이전 버전으로 되돌리면 됨. 원본 자료 변경 없음.

## 산출물 경로 적용

- 사용자 요청으로 신규 산출물에 상위 지침의 D 드라이브 outputs 경로 적용.
- output 디렉터리 생성 및 경로 확인. 구체적 개인 경로는 ignored notes에 기록.
- 기존 개발계획서·검수 문서와 업무 원본은 이동하지 않음. 신규 산출물 경로 변경은 기존 자료 이전 승인을 의미하지 않음.
- Git 커밋·원격 반영 없음. 다음 생성 산출물부터 적용.

## Outlook 대상 확정

- 사용자 결정: 받은 편지함과 보낸 편지함, 최근 1개월. 별도 보관 폴더 없음.
- 개발계획서와 로컬 자료 기록에 반영. 수신·발송 기간 판정 기준 구분.
- 검증: 변경 후 해당 항목 재조회. 실제 자동수집은 아직 미구현이며 이번 단계에서 메일 수집·업로드를 실행하지 않음.
- 다음 작업: 첫 사례에 사용할 제품·고객 자료 선정과 소량 수집 기술 검증.
- 원본 보존·커밋/원격 상태는 동일. 복원은 이번 문서 변경만 되돌리면 됨.

## 첫 제품 원본 후보 선정

- Dasan 고객 폴더 및 공용 100G 폴더 파일 목록에서 관련 두 P/N 문서 선별.
- Datasheet DS-10584 Rev00, DS-9829 Rev03의 첫 페이지 사양과 문서일 확인. 관련 FTA 두 문서는 MTBF 보고서이며 패킹 사양서가 아님을 확인.
- 산출물은 지정한 D 드라이브 outputs에 작성. 개인 원본 경로·사양은 해당 로컬 산출물에만 기록.
- 검증: UTF-8 결과 파일 재조회·존재 확인. PDF 전체 사양표/레이아웃·현재 판매상태·최신본 여부는 미검증. Python 첫 조회에서 출력 인코딩 오류가 발생하여 UTF-8 stdout 설정 후 재실행 성공.
- 원본 수정·복사·외부 업로드·메일 발송 없음. Git 커밋·push 없음.
- 다음: Datasheet 전체 주요 사양·Ordering Information 구조화, 남은 사례 및 운영 조건 확인. 0단계 전체 완료 아님.
- 복원: 신규 산출물과 기록만 추가했으므로 원본 복원 불필요.

## 초기 제품 데이터 구조화

- 두 Datasheet 전체 페이지 텍스트 및 Order Information 조회. 주요 제품검색 필드 2건을 로컬 JSON 및 설명 문서로 작성하여 D outputs에 저장.
- 제품군 속도와 실제 Bit Rate, 매체별 거리, Case 동작 온도와 보관 온도, 파장 nominal과 Typical을 구분. 문서 페이지·표 근거 연결.
- 검증: 저장한 JSON을 새로 파싱, 제품 2건·고유 P/N 2건·원본 경로 존재 확인. 실제 DB 가져오기·검색 UI/E2E·도면 검수는 미실행.
- 현재 판매 상태·최신 Revision·가격·납기·PLM 담당자는 미확인으로 보존. 패킹 사양서 확보 완료로 처리하지 않음.
- 다음: 다른 제품군의 필드 검토 또는 남은 업무 검수 사례 선정, Outlook 소량 기술 검증 및 운영 조건 확인.
- 원본 수정·외부 업로드·커밋/push 없음. 신규 산출물이므로 원본 복원 불필요.

## 두 번째 업무 사례 후보 확인

- 최근 1개월 받은/보낸 편지함에서 사양 중심 제품 문의 후보를 조회. 관련 고객 수신 1통과 회신 3통으로 다회차 처리 흐름 확인.
- 변경: CASE-02 후보를 검수 문서에 기록하고 상세 분석은 D outputs에 저장. 메일 원문·개인 연락처·견적 금액은 복제하지 않음.
- 검증: 저장 산출물 재조회. 사양별 P/N 매핑·예상 가격 후속 회신은 확인; P/N 선택 근거·HQ 확인 경로·문의 최종 종료는 미확인.
- 다음: 사용자에게 제품 선택 근거를 확인한 뒤 실제 제품검색 검수 기대 결과 확정.
- 원본·메일 수정/발송·외부 업로드·Git 커밋/push 없음. 신규 산출물 및 기록만 추가.

## 고객 가격 Excel 근거 조회

- 사용자 안내에 따라 Dasan 폴더의 견적 Excel 후보를 선별하고 2026 프로젝트 파일 두 개를 읽기 전용 조회.
- 회신과 일치하는 네 제품 표·첫 세 가격 및 네 번째 공백 확인. 수량별·SP/Dasan별 가격과 파일 간 차이 확인.
- CASE-02 산출물·검수 문서 보완. 최신성·정확한 사용 파일은 확정하지 않음. Excel 원본 변경·저장·계산 갱신 없음.
- 검증: 조회 셀 주소 및 메일 내용 대조, 변경 문서 재조회. EmptyCell 행 속성 오류 후 행 번호 계산 방식으로 수정하여 재조회 성공.
- 다음: 문의별 가격 근거·조건을 데이터 설계에 반영하고 나머지 검수 사례 확인.
- Git 커밋/push 및 외부 업로드 없음. 복원은 이번 기록 추가분만 되돌리면 됨.

## 납기 확인 채널 보완

- 사용자 설명으로 담당자와 WeChat에서 납기를 확인한 사실 기록. 직접 메신저 조회는 하지 않음.
- CASE-02를 다중 채널 근거 취합 사례로 정리. 확인 시각·대화 내용·담당자 권한은 미확인 유지.
- 산출물과 검수 사례 기록 보완. 기존 MVP의 수동 메신저 입력 범위를 유지하고 자동 연동을 추가하지 않음.
- 변경 후 문서 재조회. 외부 쓰기·메일 변경·커밋/push 없음.

## CASE-03 및 CASE-02 보완, Outlook 1차 가능성 확인

- 목적: 실제 반복 기술 문의를 검수 입력으로 확정하고 수집 가능성을 읽기 전용으로 확인.
- 조회: 50G 기술 문의의 고객/HQ 후속 대화, 별도 가격·납기 HQ 확인 대화. 기술 로그·키·원문을 산출물에 복제하지 않음.
- 변경: 검수 사례 문서에 두 기술 질문의 부분 답변·잔여 Action·계획/완료 구분 추가. CASE-02의 오래된 미확인 문구를 현재 확인 수준으로 수정.
- 신규 산출물: 지정 로컬 outputs에 CASE-03 타임라인 및 Outlook 가능성 보고서 작성.
- Outlook 검증: 최근 1개월 MailItem 받은 편지함 293건·보낸 편지함 48건, 각 폴더 ID 누락/중복 없음. 폴더별 표본 1건씩 ID 재조회 성공. 수신/발신 날짜 기준 구분, 비메일 2건 제외.
- 보존: 메일·Excel·PDF 원본, 사용자 변경, 실행환경 유지. 클라우드 전송·메일 발송·원본 수정 없음.
- Git: 부모 하네스 workspace-main의 작업 상태는 clean이며 CRM 경로는 ignored. CRM을 하네스 저장소에 강제 추가하거나 원격 업로드하지 않음. CRM 독립 저장소는 미설정이므로 커밋/push 없음.
- 다음: 1단계의 새 세션/중단 복구 등 운영 조건과 AI 전송 범위·계정·백업 조건 확정. 직접 답변 경로와 기능/E2E 검수는 별도 진행. 0~1단계 전체 완료로 판정하지 않음.
- 복원: 원본 변경이 없어 원본 복원 불필요. 이번에 추가한 로컬 보고서 및 문서 변경 부분만 되돌리면 됨.
