# 무료 외부 CRM 전환 작업 기록 — 2026-10-13

## 승인·보존 범위

사용자가 remote-access-design.md와 remote-access-plan.md를 승인하고 이 대화에서 직접 구현·검수를 선택했다. Cloudflare Free 화면/API, 기존 Supabase 저장, PC의 Outlook 수집을 연결한다. 도메인/DNS·유료 플랜·기존 로컬 4327·원문·로컬 메모와 업무 상태는 유지한다. 추가 전체 백업은 만들지 않았다.

## 현재 검증 지점

- 기존 Git 기준 e501a827, codex/login-access → origin/main. 기존 변경을 되돌리지 않았다.
- Cloudflare 계정 Workers Free와 기존 Supabase 조직 Free를 Chrome에서 확인했다.
- 신규 메모/이력/검토 snapshot/멱등 영수증 SQL과 입력 검증을 구현했다. 격리 PGlite 검사 3개 통과. 운영 DB에는 아직 적용하지 않았다.
- 인증 API 어댑터 기초 검사 4개 통과: 만료·Origin 차단, 최신 업무 재대조, PC 실행 요청 대기, 메모 입력 검증. 실행 요청 SQL과 외부 화면·PC Agent는 미완료다.
- 공식 Wrangler 4.150.0 설치. OAuth OS 자격증명 저장용 공식 keyring helper는 Wrangler 관리 캐시에 설치했다. 로컬 프로젝트의 불필요한 keyring 의존성은 제거했다.
- 사용자가 Wrangler의 최소 배포 권한을 승인했다. 그러나 로그인 콜백이 연결 거부되어 CLI 인증은 아직 미완료다. 코드에서 콜백 수신 제한이 120초임을 확인했고, 기본 브라우저 열기 대기와 승인 지연을 분리해 재연결한다. 토큰·인증코드·자격증명은 읽거나 기록하지 않는다.
- Supabase CPU 경고를 확인했다. 읽기 전용 상태 조회는 성공했다. 유료 변경이나 세션 강제 종료는 하지 않았다.

## 판단과 다음 작업

### 배포·운영 검증 갱신

Wrangler OAuth 연결을 완료했다. 인증은 암호화 파일과 Windows Credential Manager에 저장되며 승인된 최소 권한만 사용한다. 다른 서비스용 권한 부족 안내 때문에 권한을 확대하지 않았다.

무료 외부 주소 https://sp-sales-crm.piaoenya.workers.dev 에 실제 Worker/API와 최신 업무 UI를 배포했다. 운영 신규 테이블 5개 적용 및 snapshot 영수증을 전체 자료 대신 SHA-256 hash로 보존하는 함수 개선을 적용했다. 적용 전/후 기존 문의 12·Action 13·메시지 8을 대조했다. DB 크기는 최초 약 15.2MB였다. RLS 개별 운영 조회와 최종 기능 대조는 이어서 수행한다.

로그인한 Chrome에서 업무 조회, 가상 메모 생성·수정·서버 재조회, 가상 문의 생성·원문/제품/회신/Action 화면 및 3일 기본 기한을 확인했다. 기존 검증 고객에만 테스트 문의를 만들었으며 실제 고객 문의의 상태·기한은 변경하지 않았다. 익명 메모·analysis 요청 401, 다른 Origin 저장 요청 403을 실제 배포에서 확인했다.

Windows 포트 제외 목록에 4297~4396이 있어 기본 4327 서버가 EACCES로 시작되지 않았다. 기본 진입 설정은 4327로 보존하고 PC Agent 검수 인스턴스만 CRM_LOCAL_PORT=14327로 실행했다. 전역 포트 예약/방화벽/DNS 변경은 없다. 사용자는 별도 Chrome PC 탭에 로그인했다. 메모의 기존 SQLite 건수는 0으로 이관할 기존 메모가 없었다.

PC 연결 후 운영 snapshot 종류 4개를 확인했다: analysis 약 44.8KB, handling 약 14.5KB, sources 빈 목록, status 약 3.6KB. 새 메일 직접 수집 없이 보존된 분류/관측을 먼저 동기화했다. 새 메일의 자동 확인은 평일 서울 10~18 정각, 수동 실행은 요청 큐를 사용한다. Agent 인증은 메모리의 검증된 액세스 토큰이며 PC Chrome의 유효 연결이 필요하다. 아직 PC 중단·복귀와 실제 수동 요청 완료 검수는 남아 있다.

전체 Node 검사 최신 실행 175개 통과, 이후 메모 UI의 로그아웃/지연 응답 검사 1개 추가 통과. 최종 전체 회귀와 커밋은 미완료다.

Ruling: 한 번의 analysis 요청이 Free Worker의 subrequest 한도를 넘지 않도록 최신 Inquiry/Action을 소유자별 두 배치로 대조한다. 기존 loopback API는 유지한다.
Ruling: 영수증에 반복 snapshot 본문을 저장하지 않고 hash를 기록한다. 응답 유실의 동일 요청 대조를 보존하면서 무료 DB 저장량을 줄인다.

Ruling: 기존 문서 체계를 유지해 승인된 설계·계획은 docs/에, 실제 진행은 이 작업 기록에 남긴다. 기존 기획서에 검증 로그를 섞지 않는다.

남은 작업은 요청 큐/RLS 검증, 외부 API와 최신 UI, Windows 동기화, 운영 추가 스키마 적용, 무료 배포, 실제 로그인 및 PC 연결 중단 검수다. 현재 결과를 외부 CRM 완료로 판정하지 않는다.

## 복원·커밋

### 최종 검토·중단 검수 갱신

실제 PC 수집 서버를 중단하고 14327 수신자가 없는 상태에서 외부 테스트 문의 제목 수정·재조회, 보존 원문과 연장 기한 2026-10-19를 확인했다. 테스트 Action만 완료하고 테스트 문의만 종료해 원문/이력을 보존했다. 테스트 메모도 완료 보관했다. 기존 실제 영업 업무는 바꾸지 않았다. 운영 RLS 5개 모두 활성·SELECT 정책 5개, 수동 큐 요청 1개 처리·미처리 0개를 확인했다.

PC 복귀에는 프로젝트 전용 start-crm-sync.cmd를 추가했다. 기존 진입 스크립트는 보존하고 launcher의 포트 옵션만 확장했다. 전역 환경변수/예약/자동 시작은 추가하지 않았다. 실제 로그아웃에서 업무·원문·메모 DOM 제거를 확인했고 최종 배포를 적용한 새 로그인 세션 검수는 사용자 로그인 후 이어서 수행한다.

executing-plans의 마지막 전체 검토에만 별도 읽기 전용 reviewer를 사용했다. 중요한 발견 2개(소비된 timer로 인증 재연결 불가, 처리 지연으로 정각 누락)를 실패 테스트로 재현하고 한 번의 수정 단계로 해결했다. 갱신 토큰 재연결·정각 catch-up 검사 4개 통과. 정각을 지난 첫 중간 시간 로그인은 즉시 새 수집을 시작하지 않는다. 최신 전체 Node 178개 및 Python 103개 회귀 결과를 최종 실행으로 확인한다.

남은 운영 조건: Outlook이 현재 꺼져 있어 실제 신규 메일 수집 성공은 검수하지 않았다. PC Chrome 인증 연결 유지와 Outlook 실행이 필요하다. 실제 새 요청 저장/정각 장기 검수·1주 실사용, 추가 소유자 실제 계정 E2E는 합성 권한 검사와 구분한다. Free의 비활성/자원 한도는 유지한다.

### 추가 요청 — 왼쪽 메뉴 고정

사용자가 스크롤 중에도 왼쪽 메뉴를 계속 보이게 요청했다. web/style.css의 데스크톱 side-nav에 sticky/top:0/align-self:start/100dvh 및 메뉴 내부 세로 스크롤을 적용했다. 모바일 기존 레이아웃을 유지한다. 로컬·외부 빌드 및 무료 배포 후 Chrome에서 본문 scrollY 약 762px에서도 navLeft=0/navTop=0과 메뉴 표시를 확인했다. 초기 navTop 약 95px에서 본문 스크롤 후 상단에 고정되며 내용 레이아웃은 유지된다.

초기 기초 구현 시점에는 미커밋·운영 DB 미적용이었다. 위 후속 절의 추가 스키마/배포/검수 적용을 최종 변경으로 구분한다. 기능 복원은 관련 커밋의 일반 revert로 수행하며 공개 Git 이력을 강제 변경하지 않는다. 운영 신규 스키마·검수 이력·기존 자료를 임의 삭제하지 않는다.

Ruling: 외부 조회·저장·PC 동기화의 연결 계약을 함께 검증했으므로 소스와 관련 설계/검수 기록을 하나의 수직 구현 커밋으로 묶고 공개 origin/main 반영을 확인한다. 개인 notes·메일/DB·인증 및 배포 캐시는 제외한다.

최종 코드 회귀는 Node 178/178, Python 103/103, 로컬·외부 빌드, diff 공백 검사를 통과했다. 최종 배포 버전 d052139c-756c-4acf-9e3d-66c097adf3df를 확인했다. 사용자가 마지막 외부 로그인 완료를 답했으나 현재 제어 중인 외부 탭은 여전히 연결 창이며, 로그인된 PC 탭만 확인되어 최종 새 외부 세션 UI 대조는 보류로 기록한다. 기존 실제 외부 세션의 업무/메모 저장·PC 중단/로그아웃 검증과 혼동하지 않는다. 사용 중인 PC 탭은 유지했다.

소스·관련 문서 커밋 00b5bd3ca1ca7eaa4f94288da06e8f2c1a6f1037을 사용자 소유 공개 origin/main에 push하고 ls-remote의 동일 hash를 확인했다. 변경된 36개 파일의 고확신 자격증명 패턴 검사는 0건이다. 이는 모든 형태의 비밀 검출 보장이 아니며 .env·notes·메일/DB/캐시·Wrangler 인증/배포 설정은 계속 Git 제외한다. 이 커밋/원격 확인 이력만 후속 문서 커밋으로 보존한다.

### 최종 독립 점검 — 정적 응답 보안 헤더 보완

외부 HTTP 실측에서 API 응답에는 보안 헤더가 있지만 `/`, `/app.js`, `/style.css`에는 없음을 발견했다. 정적 파일을 먼저 응답하는 Cloudflare Assets 설정 때문에 Worker의 응답 헤더 코드가 실행되지 않는 것이 원인이다. 공식 정적 Assets `_headers` 방식을 적용했다. web/remote-headers를 tools/build-remote.mjs에서 dist-remote/_headers로 복사하며, 정적 요청을 모두 Worker로 전환하지 않아 기존 무료 실행 방식은 유지한다. CSP·Referrer-Policy·nosniff·Permissions-Policy·HSTS를 정적 응답에도 적용했다. 로그인·업무 자료·원문·기존 메뉴 고정과 포트 설정을 보존한다.

추가 패키징 검사 실패를 재현한 뒤 수정했으며, 최종 전체 Node 179/179, 이번 마무리 점검의 Python 103/103, 외부 빌드를 통과했다. 배포 버전 d5962bd9-c8d9-45d8-b627-2885df8f92aa에서 위 세 정적 경로의 200과 보안 헤더, 익명 메모 API의 401 및 보안 헤더를 실제 HTTP로 확인했다. 전체 백업이나 운영 DB 변경은 추가하지 않았다.

사용자가 Chrome에 외부 CRM을 열었다고 답한 뒤 사용자 탭 목록에서 외부 주소를 확인했다. 그러나 해당 탭의 실제 화면 읽기가 시간 초과했고 이후 제어 탭 목록은 비어 있었다. 따라서 최신 배포의 로그인된 새 세션 화면 검수와 PC 복귀의 실제 재동기화는 확인 완료로 처리하지 않는다. 당시 PC 서버 14327은 실행 중이었으나 Outlook은 실행되지 않았다. 기존 세션에서 통과한 업무/메모 저장·PC 중단·로그아웃 검증은 유효하며, 새 세션 검수와 신규 메일·정각 장기 운영 검수는 보류다. 브라우저 제어가 실제 화면을 읽을 수 있도록 복구되면 기존 로그인 세션부터 확인하며 자격증명을 반복 요구하지 않는다.

변경 파일은 web/remote-headers, tools/build-remote.mjs, tests/remote-worker.test.mjs와 이 작업 기록·개발 보고서다. 해당 소스 수정은 일반 revert 후 재배포로 복원할 수 있다. DB·고객 업무·개인 Chrome 설정은 이번 수정 대상이 아니다. 최종 선별 커밋·원격 반영 결과는 아래 마감 기록에서 확인한다.
