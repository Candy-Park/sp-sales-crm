# CRM 통합 사전 점검 — 2026-10-21

## 범위와 상태

사용자는 sp-sales-crm을 통합 기반으로 선택하고, 앱 수정 전에 Source Photonics CRM의 사용 환경과 데이터 중복을 읽기 전용으로 확인해 달라고 요청했다. 로컬·배포 환경은 확인했고 **현재 클라우드 데이터 대조는 인증 대기**다. 전체 중복/고유 건수를 확인한 상태가 아니다.

## 읽기 확인과 보존

- A의 시작 브랜치·원격·변경 없음 상태를 확인하고 `git pull --ff-only`: Already up to date. B는 기존 untracked 폴더와 HEAD를 보존하고 읽기만 수행.
- B 기본 실행 스크립트의 DB 경로와 실제 파일을 대조했다. 기본 업무 DB와 별도 QA DB를 구분했다. A 로컬 메모·Outlook 캐시는 원격 업무 정본을 대신하지 않는다.
- DB 파일 5개를 SQLite `mode=ro`, `PRAGMA query_only=ON`으로 조회했다. `quick_check` 모두 ok, 조회 전후 SHA256 모두 일치. 서버·업무 Store 생성자·수집·복원은 실행하지 않았다.
- Chrome에서 배포된 B의 `crm-build.json`을 직접 읽어 staging과 설정된 프로젝트 일치를 확인했다. 정적 환경표식은 현재 원격 스키마·데이터의 증거가 아니다.
- Supabase 커넥터는 미연결, 기존 CLI는 인증 없음이었다. 브라우저 대시보드도 로그인 화면이므로 계정 입력·인증정보 추출·보호 우회 없이 사용자 로그인으로 인계했다. 사용자에게 토큰/암호를 채팅에 보내라고 요구하지 않았다.
- B 로컬 업무 제목과 A의 과거 메일 캐시 제목의 제한적 대조만 수행했다. 이 결과를 현재 원격 Inquiry의 중복/비중복 판정으로 확대하지 않는다. 업무 원문·개인 경로·원본 ID는 공개 Git 기록에 싣지 않는다.

## 다음 작업·복원

사용자 Supabase 연결/브라우저 로그인이 완료되면 양쪽 프로젝트·허용 소유자·원격 스키마·건수를 조회하고, 원본 참조·업무/행동·기한/완료 충돌을 대조한다. 각 결과는 중복 확정/후보/고유/판단 보류/테스트 후보로 분리하고 앱 수정 전에 다시 제시한다. 인증 없이 현재 데이터 대조가 끝났다고 보고하지 않는다.

앱·DB는 수정하지 않았으므로 원본 복원 작업이 없다. 문서는 이번 문서 커밋의 revert 또는 D의 before 사본과 차이를 검토해 복원할 수 있다. 후속 사용자 편집과 원격 데이터를 임의로 되돌리지 않는다.
