# 외부 접속 전환 설계 — 무료 한도 내 운영

작성: 2026-10-13. 상태: 사용자가 ‘이 설계대로 진행’으로 상세 설계를 승인했다. 실행 계획 작성 단계이며 실제 구현/배포 완료 문서가 아니다.

## 확정한 목적과 조건

- 사용자는 외부에서 주소로 접속하고, 현재 PC가 꺼져도 저장된 업무를 조회·수정하기를 원한다.
- 추가 유료 플랜·서비스 결제 없이 기존 Supabase와 Cloudflare Free를 사용한다. 새 프로젝트/유료 도메인/AI API를 추가하지 않는다.
- 우선 무료 workers.dev 주소에서 검증한다. 사용자는 ajsol.co.kr/ajsol.net 도메인만 보유하며 홈페이지 보유를 전제하지 않는다. 도메인/DNS/메일 설정 변경은 이번 기본 주소 배포에서 하지 않는다.
- 기존 로컬 CRM4327과 운영 데이터/원문/메모·기한·담당 판단을 보존한다. 단순 시연 사이트가 아니라 인증된 실제 업무 조회·수정을 목표로 한다.

## 구조

외부 브라우저 → Cloudflare Workers(화면·인증된 업무API) → 기존 Supabase(Auth·소유자별 업무DB).

Windows PC의 Outlook/Local Agent → 인증된 동기화API → 동일 소유자의 필요한 메일 관측/검토 정보. PC가 꺼지면 새 수집은 중지하되 마지막 저장 업무는 계속 사용할 수 있다.

Cloudflare Tunnel로 PC 화면을 프록시하는 방식을 사용하지 않는다. 그 방식은 PC 종료 시 전체 업무 조회·수정이 중단되어 요구사항과 맞지 않는다.

## PC 상태별 동작

| 기능 | PC 켜짐·Outlook/Agent 실행 | PC 꺼짐 |
|---|---|---|
| 문의·Action·기한·종료 이력 | 클라우드 저장/재조회 | 동일하게 가능 |
| 제품 후보·HQ/고객 기록 | 기존 인증API로 사용 | 동일하게 가능 |
| 업무 홈·고객/HQ·검토 정보 | 동기화한 최신 정보+저장 업무 표시 | 마지막 동기화 정보+최신 저장 업무 표시 |
| 메모 | 인증된 클라우드 메모와 보존된 로컬 메모 대조 | 클라우드에 반영한 메모 조회·수정 |
| 새 메일 수집·분류/대조 | 기존 평일10~18 조건과 수동 확인에 따라 실행 | 수집 미실행/대기, 마지막 성공 시각 표시 |
| 원문 | 이미 DB에 보존된 원문 및 필요한 승인 범위 | DB 저장 원문 가능; PC 전용 보류/긴 원문은 불가를 명시 |

새 메일이 없거나 PC가 꺼진 것을 업무0건/처리완료로 표시하지 않는다. 모든 변경은 기존 약속일·미완료 필수Action·질문 충분성/종료 판단을 유지한다.

## 기존 코드와 전환 범위

- src/worker.mjs·src/api.mjs의 기본 업무/제품/커뮤니케이션 API를 재사용한다. 기존 Auth 서버 검증·sales_access 허용목록·owner_id/RLS를 유지한다.
- 최신 task-preview 업무 홈/메뉴/Frosted/Pretendard UI를 외부용 진입점에서 연결한다. 이전 web/app.mjs 기본 화면만 배포해 최신 기능을 완료로 취급하지 않는다.
- 현재 followups/담당 검토 정보는 로컬 Python/SQLite/JSON에 의존한다. 인증된 소유자별 동기화 자료를 클라우드에서 읽는 어댑터가 필요하다. 정적 번들/공개 Git/로그에 실제 메일·고객 자료를 넣지 않는다.
- 현재 메모는 node:sqlite 기반의 PC 저장이다. 클라우드용 메모 저장·이력/요청 영수증·버전 충돌 처리가 필요하다. 기존 개인 메모를 삭제/자동 덮어쓰기 하지 않는다.
- 메모/검토 동기화에는 기존 업무 테이블과 구분한 소유자별 테이블·최소 RPC를 추가 검토한다. 기존 테이블을 drop/truncate/재생성하거나 기존 CRM과 통합하지 않는다.
- Windows Agent는 외부 브라우저에서 직접 COM을 호출하지 않는다. 인증된 동기화/실행 요청과 PC 처리/결과를 구분하고 PC 부재/실패/응답 유실/재실행을 표시한다. 인증정보를 메일DB·실행인자·Git/로그에 남기지 않는다.

## 접근·보존

- 로그인 전 업무/메일/메모 조회 차단. UI 숨김만으로 보호하지 않고 API/DB에서 검사한다.
- 기존 로그인 계정·소유자 규칙을 재사용한다. 공개가입/다른 계정 접근·service_role 클라이언트 노출을 추가하지 않는다.
- 정적 파일/글꼴/공개 로그인 설정 외 응답은 no-store. HTTPS, 정확한 origin/경로/입력 크기 제한, CSP와 안전한 텍스트 출력을 검증한다.
- 동기화 요청은 서버에서 사용자/허용목록·소유자·고정 식별자/해시·버전을 검증한다. 사용자 제공owner_id를 권한 근거로 쓰지 않는다.
- 로컬→클라우드 최초 대조는 건수/식별자/내용을 확인하고 기존 원문·메모를 그대로 보존한다. 불일치/응답 유실은 같은 요청으로 재조회/재시도한다.
- Supabase Free 계획·사용량을 먼저 확인한다. API용 별도 유료 custom domain을 켜지 않는다. Workers Free를 유지하고 유료플랜/AI호출/새VM 구매를 하지 않는다.

## 합격 기준

1. 인증된 외부 주소에서 최신 홈/메뉴·문의·Action·기한 연장·제품/회신·메모를 저장하고 재조회한다.
2. PC 연결을 실제로 중단한 상태에서 저장 업무/클라우드 메모 조회·수정이 성공하고 새 메일 수집 미실행 안내가 정확하다.
3. 익명/미허용/다른 소유자·오래된 응답/버전·중복 요청은 원문/입력/상태를 훼손하지 않는다.
4. 로컬4327과 클라우드의 같은 업무 변경을 재조회해 대조하고, 원문·약속일·종료 규칙·memo 충돌을 확인한다.
5. PC/Outlook/Agent 실행 시 실제 수신/발신 수집→동기화→외부 화면 대조, 반복 후 중복 없음 확인.
6. Cloudflare/Supabase가 무료 플랜이며 유료 리소스가 추가되지 않았음을 계정에서 확인한다. 무료 한도 내 동작이며 무제한/영구 가용성 보장이 아니다.

## 실행 전 필요한 사용자 단계

Cloudflare 개인 계정 로그인과 위 상세 설계 검토가 필요하다. Chrome에 Cloudflare 로그인 화면을 열었다. 비밀번호/OTP는 사용자가 직접 입력하며 채팅/로그에 기록하지 않는다. 계정이 없으면 약관 동의/계정 생성의 최종 단계는 사용자가 수행한다.

설계 검토 후 실행 계획과 검수/복원 단위를 정한다. 실제 배포 전 로컬/격리 환경 검수를 마치고 인증정보는 승인된 계정의 비밀 설정으로만 전달한다. 무료 기본주소는 실제 계정에서 생성한 값을 확인하며 가짜 URL을 완료 결과로 제시하지 않는다.
