# sp-sales-crm 개발 보고서

2026-10-07 구현 결과 기준. 실제 구현한 기능과 검증 한계를 보고한다. 요구사항과 주요 결정은 [기획서](development-plan.md), 조사·잠정 의견은 [검토·결정 기록](decisions/review-and-decisions.md), 변경/백업/검증 상세는 [작업 기록](README.md)에서 관리한다.

| 구현 기능 | 확인한 결과 | 남은 확인 |
|---|---|---|
| 로그인·기본 업무 | 실제 로그인, 본인 조회, 수동 고객/문의 등록, Action 편집·완료·취소, 종료와 이력 조회 확인 | 토큰 만료 UI, 경합 후 커밋 순서별 결과 |
| 100G LR4/SR4 검색 | 사양 비교·출처·미확인 표시·후보 이력 구현. 두 제품 실제 DB 적용, 합성 ROLLBACK·사후 권한 검사 통과 | 최신 화면의 사용자 로그인 제품 E2E, 후보/종료 동시 실행 |
| 수동 HQ·고객 회신 | 수동 초안/복사·실제 발송/수신·별도 번역·질문별 검토·이전 근거·대기 대상·종료 차단 구현. 격리 UI 흐름 통과 | 새 회신 DB 반영 확인, 실제 SQL/RLS·사후 검사·로그인 E2E |

원문과 이전 검토 근거를 보존하고, 초안·복사를 실제 발송과 구분해 업무 상태 오판을 줄였다. 받은 답변만으로 질문을 완료하지 않으며 미답변/부분 답변이나 조회 실패·잘림이 있으면 문의 종료를 막는다. 저장 결과가 불확실할 때 입력과 요청 식별자를 유지한다.

최종 로컬 Node 58개, Python 9개 테스트 및 브라우저 빌드를 통과했다. API/회신 UI 테스트는 가상 네트워크 응답을 사용한다. 제품 DB 실제 검증과 회신 DB 미검증을 혼동하지 않는다. 전체 MVP 완료를 의미하지 않는다.

AI 서비스·모델·비용은 아직 선택하지 않아 호출하지 않는다. 실제 Outlook 자동 수집·복원 검증·1주 실사용과 배포는 남아 있다. 기존 CRM과 Supabase sp-crm, 무료 플랜과 로컬 전용 Git 조건을 유지했다.
