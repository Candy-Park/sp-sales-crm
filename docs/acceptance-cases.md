# Source Photonics sales CRM — 업무 검수 사례

작성일: 2026-10-06. 개발계획서 0단계의 검수 사례 선정 기록이다. 메일 원문·연락처·첨부파일은 복제하지 않는다. 실제 업무 사례는 로컬 조회로 확인했으며 외부 업로드하지 않았다.

## CASE-01. P/N이 확정된 두 제품의 자료 요청

### 관찰된 처리 흐름

1. 고객이 두 제품의 패킹 사양서를 제출 목적으로 긴급 요청했다.
2. 사용자가 담당자의 휴무에 따른 지연과 예상 답변일을 고객에게 먼저 안내했다.
3. 사용자가 HQ 담당자에게 두 제품의 자료를 영어로 요청하고 고객 원문을 포함했다.
4. 조회 시점의 해당 날짜 메일에서 HQ 답변 및 최종 자료 전달은 확인되지 않았다. 사례는 진행 중이며 최종 처리까지 검증한 것으로 보지 않는다.

### 기대 데이터와 동작

- Inquiry는 하나이며 제품 연결은 두 개다. 두 제품의 상세 P/N은 실제 검수 시 지정된 원문과 대조한다.
- 제품 검색 없이 Inquiry 상세에서 HQ 문의로 이동할 수 있다.
- 고객 중간 회신과 HQ 발송 메시지가 함께 기록된다. 고객 중간 회신만으로 Closed 처리하지 않는다.
- 대표 상태는 Waiting for HQ이며, 고객에게 알려준 예상 답변일과 Action의 Due Date를 구분한다.
- 고객 요청의 긴급성과 제출 목적을 보존한다. 고객이 정확한 마감일을 제시하지 않았다면 임의 마감일을 만들지 않는다.
- 고객 대화와 HQ 대화의 Outlook ConversationID가 달라도 같은 Inquiry에 연결할 수 있다.
- 영문 초안 검토 시 긴급성·제출 목적·요청일의 전달 여부를 확인할 수 있다. 기존 발송문에 없는 내용을 이미 전달한 사실로 표시하지 않는다.
- Follow-up 날짜는 사용자 설정 또는 승인된 제안으로 기록하며, 고객에게 안내한 예상 답변일을 자동으로 확정 기한으로 취급하지 않는다.

### 검수 절차

| 순서 | 검수 행동 | 기대 결과 |
|---|---|---|
| 1 | 고객 메일을 수집 대기 목록에서 신규 문의로 등록 | 한 Inquiry 생성, 원문·채널·수신 시각 보존 |
| 2 | 두 제품을 같은 문의에 연결 | 제품 두 개 표시, 검색 강제 없음 |
| 3 | 실제 고객 중간 회신을 연결 | 중간 안내로 표시, 미해결 문의 유지 |
| 4 | 별도 대화 ID의 HQ 발송 메일을 기존 문의에 연결 | 새 Inquiry 중복 생성 없이 동일 문의에 표시 |
| 5 | 실제 HQ 발송 기록을 확인 | Waiting for HQ, 담당자·발송 시각 표시 |
| 6 | 예상 답변일과 사용자가 정한 Follow-up 날짜 기록 | 두 날짜의 의미 구분, Action 대시보드 표시 |
| 7 | 같은 메일을 재수집 | 메시지·Inquiry 중복 없음 |
| 8 | 이후 HQ 답변을 연결하고 제품별 자료 확인 | 두 제품 중 빠진 자료가 있으면 미해결 항목 유지 |
| 9 | 최종 고객 자료 전달과 남은 Action 확인 | 실제 회신 기록 보존, 종료 조건 충족 후 Closed |

8~9번은 후속 메일이 확보된 뒤 실제 검수한다. 현재는 계획된 검수 절차이며 구현 결과가 아니다.

### 개발계획서 연결

A02 수동 문의·데이터 보존, A03 메일 연결·중복 방지, A07 HQ 직접 경로, A08 발송과 초안 구분, A09 부분 답변, A11 후속 업무, A12 기본 이력·종료를 검증한다.

## CASE-02 — 사양별 제품 연결 및 다중 채널 고객 회신

최근 1개월 메일에서 P/N 없는 네 가지 PON 사양 요청, 중간 안내, 제품별 P/N·납기·가격 표 회신, 이후 예상 가격 추가 회신을 확인했다.

검수 범위는 요구사항 여러 줄과 제품 연결, 부분 답변, 후속 업데이트, 예상/확정 가격과 납기 구분이다. 상세 로컬 산출물은 지정 outputs에 저장했다.

사용자 안내 후 고객 가격 Excel을 조회하여 회신과 일치하는 네 제품의 표를 확인했다. 첫 세 가격은 회신과 일치하고 네 번째 가격은 Excel 공백이며 후속 메일에만 추가되어 있다. 정확히 사용한 파일·표는미확인이며, 수량별·가격종류별 조건과 자료 버전, Excel/후속 메일 차이를 검수에 포함한다.

추가 사용자 설명: 납기는 담당자와 WeChat으로 확인했다. 따라서 CASE-02는 고객 메일·Excel·메신저 확인·고객 회신을 하나의 Inquiry에 연결하는 다중 채널 사례로 분류한다. 메신저 확인 내용·담당자·시각·적용 제품/조건의 수동 기록을 검수하며 자동 API 연동은 추가하지 않는다. 메신저 원문과 확인 시각은 미확인이다.

추가 이메일 조회에서도 HQ 가격·납기 확인 요청과 qualification 관련 질문을 확인했다. 이 이메일은 확인 과정의 근거이며 확정 납기 답변은 아니다. 과거 샘플 가격을 현재 고객 견적에 자동 적용하지 않는다. ‘HQ 확인 없이 직접 답변’의 전체 경로는 별도 검수 입력이 필요하다.

## CASE-03 — 두 기술 문제의 부분 답변과 반복 후속 확인

고객이 50G-only 동기 검출 실패를 문의하고, 이후 Tri-mode 연결 후 반복 끊김을 추가했다. 사용자는 고객 추가 정보·HQ 확인·현장 정보를 전달했으며 HQ는 샘플 수량 확인, only FW 처리 제안, Tri-mode 분석 요청을 각각 회신했다. 최종 해결은 조회한 메일에서 확인되지 않았다.

### 기대 데이터와 검수

- Inquiry 하나에 두 제품 및 질문별 증상을 구분하고 사용자가 연결 범위를 검토한다.
- 고객 가설·HQ 가설·확정 사실을 출처와 함께 보존한다. 시험값을 제품 일반 사양으로 바꾸지 않는다.
- 샘플 수량 답변과 기술 원인 답변을 구분한다. 한 질문의 답변만으로 전체 Inquiry를 종료하지 않는다.
- 회수·반송·FW 적용·재시험과 다른 제품의 분석·추가 시험·고객 안내를 별도 Action으로 추적한다.
- 반송·통화·회의 예정은 완료 기록과 구분한다. 일정은 사용자가 확인한 후 지정한다.
- HQ 추가 답변을 관련 질문에 연결하고 미답변 질문과 남은 Action을 유지한다.
- 고객 확인과 잔여 Action 검토 후 사용자가 Closed 여부를 판단한다.

A02, A03, A05, A07, A08, A09, A10, A11, A12에 연결한다. 상세 타임라인은 로컬 outputs에 저장했다. 세 사례 선정은 구현 검수 통과를 의미하지 않으며, 직접 답변 경로·중단 복구·접근통제·백업 등은 별도 검증이 남는다.

## 메일 분류 대표 20건 — 2026-10-09 선정

사용자 요청의 1단계인 대표 메일 선정만 수행했다. 기존 받은 메일 295건에서 서로 다른 대화 20개를 선정했으며, 기존 독립 평가용 10개 대화와 겹치지 않는다. 개별 메일 식별자·제목·최신 본문 발췌와 검수용 빈 정답 칸은 ignored 로컬 자료에만 보관한다. 원문·가격·연락처·정답 키를 공유 문서에 복제하지 않는다.

| 선정 묶음 | 건수 | 확인할 구분 |
|---|---:|---|
| 고객 업무 후보 | 5 | 고객 관계·요청과 기존 문의 연결 여부 |
| HQ 업무 후보 | 5 | HQ 요청/답변과 다음 할 일 |
| 기존 확정 스팸 | 2 | 기존 사용자 확정의 기준 확인 |
| 보안 알림 | 1 | 보안/격리 통지와 직접 업무 |
| 업무 알림 | 1 | 시스템 통지와 사람의 요청 |
| 뉴스레터 후보 | 2 | 정기 소식과 직접 업무 요청 |
| 긴 본문 보류 | 2 | 원문 보존·자동 처리 보류 |
| 판단 보류 | 2 | 관계/의도가 불명확한 경계 사례 |

위 분류는 선정용 로컬 규칙 신호이며 새 사용자 정답은 0건이다. 기존 확정 스팸 2건은 새 독립 평가 정답으로 계산하지 않는다. 날짜·발신 도메인·첨부 유무·인용/다국어 신호의 다양성을 고려한 목적 표본이므로 전체 메일의 비율이나 정확도를 그대로 추정하지 않는다. 첨부 내용은 열지 않았다. 최신 본문은 인용 경계를 적용한 제한 발췌이며 실제 의미 판단에 부족하면 보존 원문과 대화를 추가 확인한다.

다음 단계는 실제 정답 분류·상대 역할·기대 업무를 사례별로 확인하는 것이다. 분류 확정·문의 연결·Action 생성·업무 제외·AI 호출은 이번 선정에 포함하지 않았다. 선정의 원본 보존/검증 이력은 Outlook 작업 기록의 같은 날짜 절을 따른다.

2026-10-09 사용자 확인 후속: 위 20건의 CRM 처리 판단을 사용자 확인으로 갱신했다. 고객 업무 5·HQ 업무 2를 등록 후보로 유지하고 13건은 등록 불필요로 정리했다. 담당 범위 밖 2건을 제외하고, 기존 HQ 후보 1건을 사용자 담당 고객 업무로 변경했다. 영업 담당과 주된 회신 담당을 구분했다. 최초 선정의 긴 본문 보류는 2건이며 모두 등록 불필요한 DWT 보고서였다. 최신 사용자 확인 결과는 별도 ignored 로컬 검수표에 유지하고 최초 선정 자료도 보존한다. 업무의 구체적인 다음 할 일·기한이나 분류기 전체 정확도까지 확인한 결과는 아니다. 실제 CRM 저장/제외·Outlook 이동/삭제는 실행하지 않았다. 일반 등록 기준은 기획서와 검토·결정 기록의 같은 날짜 절을 따른다.
